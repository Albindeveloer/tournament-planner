### Migration runner behavior (`migrate.ts`)

The migration runner does the following:

1. Connects to `auth_db` using the shared Postgres pool.
2. Creates `schema_migrations` if it does not exist.
3. Reads migration files from `apps/auth-service/migrations`.
4. Loads already-applied migration IDs from `schema_migrations`.
5. Executes pending `.sql` migrations in filename order.
6. Inserts each successful migration filename into `schema_migrations`.
7. Uses a transaction (`BEGIN`/`COMMIT`) and rolls back on failure.

### Commands used

Run auth-service migrations:

```bash
npm run migrate --workspace=@tournament-planner/auth-service
```

### Verify tables in pgAdmin

After running migrations successfully, verify `public` tables in `auth_db`:

```sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'
     AND table_type = 'BASE TABLE'
ORDER BY table_name;
```
